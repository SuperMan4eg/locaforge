# Архитектура LocaForge

## Назначение

LocaForge импортирует JSON, CSV/TSV, Gettext PO и XML в переносимый проект `.lfproj`,
поддерживает редактирование, проверку, перевод и review локальной моделью, а затем
восстанавливает исходный формат при экспорте. Исходные файлы пользователя не изменяются.

## Правило зависимостей

Зависимости направлены внутрь:

```text
Presentation ─┐
Infrastructure├──> Application ───> Domain
App/bootstrap ─┘
```

- `domain` содержит сущности, value objects и бизнес-правила.
- `application` содержит сценарии, DTO, `ProjectWorkspace` и внешние порты.
- `infrastructure` реализует форматы, SQLite, `.lfproj`, Ollama и поиск метаданных.
- `presentation` содержит PySide6 widgets, models, workers и UI-контроллеры.
- `app` служит composition root и точкой входа.

`domain` и `application` не импортируют PySide6, `sqlite3`, HTTP-клиенты или конкретные парсеры.

## Структура пакетов

```text
src/locaforge/
  app/                    # composition root, логирование, запуск
  domain/                 # проекты, записи, профили, настройки, история
  application/
    ports/                # хранение, форматы, LLM, метаданные, glossary, TM
    use_cases/            # import/export, edit, translate, validate, review
    dto/                  # данные границ
    services/             # общие прикладные сервисы
  infrastructure/
    formats/              # JSON, CSV/TSV, PO, XML
    persistence/          # SQLite и контейнер .lfproj
    llm/                  # клиент Ollama
    metadata/             # необязательные сетевые метаданные проекта
  presentation/           # Qt UI, контроллеры, workers, локализация
  resources/locales/      # встроенные языковые пакеты интерфейса
```

## Основные сценарии

Импортёр разбирает исходный файл в независимые от формата записи и метаданные round-trip.
Сценарии работают только с объектами domain и портами. SQLite-репозиторий хранит проект,
а контейнер `.lfproj` упаковывает базу для переноса. Экспортёр объединяет текущие переводы
с сохранёнными метаданными и транзакционно записывает новый файл назначения.

Перевод и review определяют эффективные [настройки моделей](development.ru.md#наследование-настроек-моделей),
строят ограниченный контекст проекта, вызывают LLM-порт, валидируют ответ и записывают
обратимую операцию. Контроллеры presentation координируют сценарии без бизнес-правил.

## Границы координации

`ProjectWorkspace` — stateful-фасад совместимости для текущего открытого проекта и его сессии.
Он получает репозиторий проекта, делегирует операции и обновляет активный агрегат после
сохранённых изменений. Выбор формата, хранение проекта, импорт и экспорт, редактирование
переводов, review, валидация, история, терминология и настройки моделей находятся в отдельных
сервисах `application/services`.

`MainWindow` служит поверхностью композиции Qt, а не владельцем каждой пользовательской
операции. Widget builders создают связанные наборы виджетов, action builders — наборы действий
меню и панелей, а presentation-контроллеры реализуют навигацию, жизненный цикл проекта,
импорт и экспорт, перевод, review, настройки, прогресс и политики окна. Контроллеры используют
стабильный API `ProjectWorkspace` и не обращаются напрямую к infrastructure-адаптерам.

Такое разделение позволяет тестировать domain-решения и координацию хранения без Qt, сохраняя
для desktop-оболочки единую точку интеграции с состоянием проекта.

## Хранение и совместимость

Проект может содержать несколько документов и форматов. Стабильные идентификаторы записей
и документов обеспечивают фильтрацию, обновление, историю и пакетные операции. Миграции
схемы выполняются при открытии; старые контейнеры остаются читаемыми. Перед использованием
проверяется целостность ZIP-данных контейнера и базы SQLite. Ручное сохранение атомарно заменяет
целевой файл и хранит три поколения резервных копий: самая новая — `.lfproj.bak`, затем `.bak.1`
и `.bak.2`. При ошибке открытия можно восстановиться из самой новой копии, не перезаписывая
оригинал и резервную копию.

## Точки расширения

Новый формат добавляется реализацией портов importer/exporter и регистрацией в composition
root. Новый LLM backend подключается через LLM-порт. Языки UI добавляются по
[руководству по локализации](localization.ru.md); пакеты языка не меняют поведение domain.

## Текущие границы

LocaForge — однопользовательское desktop-приложение. Совместное редактирование, hosted-модели
и прямое изменение исходных файлов не поддерживаются.
