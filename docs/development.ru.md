# Руководство разработчика

## Локальная настройка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
$env:PYTHONPATH = "src"
$env:QT_QPA_PLATFORM = "offscreen"
python -m pytest
python -m ruff check src tests
python -m mypy src
python scripts/check_docs.py
```

Запустите приложение командой `locaforge` или `python -m locaforge`.

## Базовые измерения производительности

До и после изменений, влияющих на производительность, запускайте воспроизводимый локальный набор:

```powershell
$env:PYTHONPATH = "src"
$env:QT_QPA_PLATFORM = "offscreen"
python scripts/benchmark_performance.py `
  --json benchmark.json `
  --markdown benchmark.md
```

По умолчанию создаются изолированные проекты на 1 000, 10 000 и 50 000 строк. После одного прогрева
выполняется пять измерений, для которых сохраняются медиана и p95 по методу ближайшего ранга. Набор
проверяет холодную композицию UI, поиск записей, статистику, поиск и фильтрацию таблицы, обновление
строки, открытие проекта, редактирование, Undo/Redo, валидацию, полную запись репозитория, ручное
сохранение `.lfproj`, autosave, поиск в памяти переводов и пакетный поиск по кэшированному глоссарию.
Временные данные удаляются после прогона.
Отчёт содержит версии Python, PySide и SQLite, сведения об ОС и процессоре.

Для быстрой проверки самого benchmark-скрипта используйте:

```powershell
python scripts/benchmark_performance.py --quick --skip-startup
```

Измерение Ollama включается явно, поскольку оно загружает и запускает выбранную локальную модель:

```powershell
python scripts/benchmark_performance.py `
  --ollama-url http://127.0.0.1:11434 `
  --ollama-model qwen3:8b `
  --ollama-batch-sizes 5 10 20 40 `
  --ollama-keep-alive-seconds 300 `
  --json benchmark-with-ollama.json
```

В результат Ollama входят переданные сервером длительности загрузки, обработки prompt и генерации,
количества токенов, скорость генерации и число строк в минуту для каждого размера пакета. Значение
`-1` оставляет модель загруженной, а `0` выгружает её после каждого запроса и позволяет измерить
холодную загрузку. Не сравнивайте результаты, полученные с разными режимами питания, фоновой
нагрузкой, версиями Python или настройками модели. Benchmark является диагностическим и намеренно
не содержит временных порогов для CI.
Зафиксированная исходная точка текущего компьютера разработчика хранится в
`benchmarks/baseline-windows-cpython314.json`.

Целевой прогон этапа 6 хранится в `benchmarks/ollama-gemma4-12b-stage6.json`. Для `gemma4:12b`
после прогрева выполнено по три измерения, и модель вернула все запрошенные строки. Пакет 5 показал
лучшую медианную пропускную способность — 124,2 корректной строки/мин при p95 4,03 с. Поэтому он
используется для новых и ранее не настроенных профилей; явно сохранённые размеры пакета не меняются.

Измерения CPython JIT, Cython и Nuitka на этапе 7 и принятое решение по упаковке описаны в
[отчёте об эксперименте с runtime и компиляторами](performance-stage7.ru.md).

## Наследование настроек моделей

`ApplicationSettings.model_settings` — глобальный пользовательский профиль. Он содержит
модель перевода, необязательную модель reviewer, режимы reasoning, timeout, размер пакета,
Ollama keep-alive и system prompts. Профиль хранится в настройках Qt и передаётся
`ProjectWorkspace` при запуске. Безопасный диагностический отчёт содержит только агрегированные
времена Ollama и количества токенов; входы и ответы модели, prompts и содержимое проекта в него
не входят.

Каждый проект также хранит `model_settings` и `model_settings_override_enabled`:

- при выключенном override `resolve_model_settings()` возвращает текущий глобальный профиль;
- включение override сначала копирует текущий эффективный профиль в проект;
- при включённом override используются проектные значения, не зависящие от будущих глобальных изменений;
- изменение настроек моделей открытого проекта включает его override;
- отключение override возвращает живое наследование, не удаляя сохранённый снимок проекта;
- старые проекты с собственными настройками мигрируют с включённым override, а новые проекты
  по умолчанию наследуют глобальные настройки.

URL сервера Ollama относится к приложению. Проектные настройки моделей сохраняются в SQLite
внутри `.lfproj`. Такое разделение сохраняет переносимость проекта и позволяет каждой
установке использовать собственный локальный endpoint Ollama.

## Соглашение о документации

Английская версия является основной на GitHub. У каждого Markdown-документа, кроме `LICENSE`,
должны быть английский файл и пара `.ru.md`. Оба начинаются переключателем `English | Русский`,
а ссылки ведут на язык читателя, если целевой перевод существует. Перед commit запустите
`python scripts/check_docs.py`; CI проверяет пары, переключатели и локальные ссылки.

## Portable-сборка Windows

```powershell
python -m pip install -e ".[build]"
.\scripts\build_windows.ps1
```

Скрипт создаёт `dist/LocaForge/LocaForge.exe` и формирует архив с версией. Исполняемый файл
поддерживает две проверки сборки: `--smoke-test` запускает и собирает интерфейс, а `--self-test`
создаёт, редактирует, сохраняет, повторно открывает и экспортирует изолированный JSON-проект.

## CI и релизы

Тесты разделены на три уровня выполнения. Быстрый уровень не использует Qt, SQLite,
контейнеры и файловые форматы; интеграционные тесты можно запускать параллельно, а GUI-тесты
остаются последовательными:

```powershell
python -m pytest -m unit -n auto --durations=10
python -m pytest -m integration -n auto --durations=10
python -m pytest -m gui --durations=10
```

Команда `python -m pytest` выполняет единую полную последовательную проверку. CI запускает три
уровня отдельными заданиями и выводит самые медленные тесты каждого уровня.

CI запускает Ruff, mypy и быстрые unit-тесты на Python 3.12 и 3.13, integration- и GUI-тесты
на Python 3.12, проверяет документацию, собирает wheel и sdist, а также запускает обе проверки
собранного Windows-архива. Тег `v<project.version>` публикует GitHub Release с пакетами,
portable-архивом и SHA-256 checksums.
