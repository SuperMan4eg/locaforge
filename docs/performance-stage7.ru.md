# Эксперимент с runtime и компиляторами

Эксперимент этапа 7 выполнен 11 августа 2026 года на CPython 3.14.6, PySide6
6.11.1, MSVC 14.51, Cython 3.2.9 и Nuitka 4.1.3. В рабочем дереве уже находились
изменения производительности этапов 0–6. Все варианты сравнивались на одном коде
и одинаковых тестовых проектах.

## Решение

Оставить production-runtime и Windows-сборку без изменений:

- не включать экспериментальный CPython JIT;
- не добавлять Cython-расширение для проверки согласованности переводов;
- продолжать выпускать релизы через PyInstaller;
- сохранить экспериментальные скрипты и результаты, чтобы повторить проверку
  после появления стабильной поддержки Python 3.14 в Nuitka или нового
  измеренного CPU-hotspot.

Ни один вариант не достиг принятого порога ускорения пользовательских сценариев
в 15% без заметного усложнения сборки или риска совместимости.

## CPython JIT

Полный benchmark запускался с семью измерениями и тремя прогревами на проектах
из 10 000 и 50 000 строк. Состояние `PYTHON_JIT=1` проверялось внутри процесса.

Геометрическое среднее времени изменилось приблизительно на `-0,33%`. Отдельные
результаты двигались в обе стороны; в частности, статистика проекта и поиск
записи местами замедлились. Эффект неотличим от шума нагрузки и системы, поэтому
JIT остаётся выключенным.

Исходные отчёты:

- `benchmarks/stage7-cpython314-jit-off.json`;
- `benchmarks/stage7-cpython314-jit-on.json`.

## Cython

Реальный сервис `ConsistencyValidator` был собран как изолированное расширение и
измерен на 50 000 строках: 50 итераций после десяти прогревов.

| Runtime | Медиана |
| --- | ---: |
| CPython | 15,387 мс |
| Cython | 15,348 мс |

Результат `1,0025x` фактически означает отсутствие ускорения. Первая сборка также
показала риск совместимости: Cython воспринял аннотацию `dict[...]` как точный
тип и отверг используемый сервисом `defaultdict`. Для сохранения семантики Python
потребовался режим `annotation_typing=False`, в котором для этого объектного кода
почти не остаётся возможностей оптимизации.

Исходный отчёт: `benchmarks/stage7-cython-consistency.json`.

## Nuitka

Обе сборки созданы из одного рабочего дерева и прошли `--self-test` и
`--smoke-test`. Запуск измерялся на 20 offscreen smoke-прогонах после трёх
прогревов.

| Упаковка | Медиана запуска | p95 | Размер каталога |
| --- | ---: | ---: | ---: |
| PyInstaller 6.21.0 | 347,469 мс | 352,058 мс | 128 884 164 байта |
| Nuitka 4.1.3 | 315,066 мс | 318,171 мс | 92 619 856 байт |

Nuitka запускается на `9,3%` быстрее и занимает на `28,1%` меньше места.
Геометрическое среднее скомпилированного benchmark лучше CPython лишь примерно на
`2,2%`. Текстовая фильтрация ускорилась примерно на 25%, но статистика проекта и
поиск записей на некоторых размерах замедлились более чем на 20%. Кроме того,
Nuitka 4.1.3 предупреждает, что поддержка Python 3.14 пока экспериментальная.

Ускорение запуска полезно, но не достигает порога 15%, а смешанные внутренние
результаты не оправдывают замену стабильного release pipeline.

Исходные отчёты:

- `benchmarks/stage7-packaging.json`;
- `benchmarks/stage7-nuitka-runtime.json`.

## Повторение эксперимента

Установите необязательные инструменты и запустите добавленные скрипты:

```powershell
python -m pip install -e ".[experiment]"
$env:PYTHONPATH = "src"
$env:QT_QPA_PLATFORM = "offscreen"

.\scripts\build_nuitka_experiment.ps1
.\scripts\build_nuitka_benchmark_experiment.ps1

python scripts\build_cython_experiment.py build_ext `
  --build-lib build\stage7-cython\lib `
  --build-temp build\stage7-cython\temp
python scripts\benchmark_cython_experiment.py `
  --extension-dir build\stage7-cython\lib
```

Бинарные файлы и промежуточные результаты компиляции остаются в игнорируемом
каталоге `build/`.
